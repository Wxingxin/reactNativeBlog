在 RN/Expo 的 App 里，可以把“数据存到手机里”拆成三类存储介质：**内存（运行时）**、**键值存储（Key-Value）**、**SQLite（结构化数据库）**，再加上**文件系统（图片/附件）**。你问的核心是：哪些适合放哪里，以及 SQLite 数据库文件最终放在手机的什么位置。

下面给你一套可落地的分流原则。

---

## 1) 哪些数据放“普通本地存储”（Key-Value / SecureStore / AsyncStorage）

### 适合放 Key-Value 的典型数据

1. **用户偏好/设置**

   * 主题、语言、字号、开关配置、首页排序方式
   * “是否已引导过/是否同意隐私政策”等一次性标记

2. **轻量缓存（可丢）**

   * 最近一次请求时间、etag、版本号、上次同步时间
   * 小体积的接口缓存（例如 10~100 条以内，且不需要复杂查询）

3. **会话相关但体积小的数据**

   * 当前用户 id、角色、环境配置、最近选择的 workspace/project

### 存储介质选择建议

* **敏感信息（token/refresh token/密钥）**：用 **SecureStore**（Expo）或原生 Keychain/Keystore（RN），不要放 AsyncStorage/SQLite。
* **非敏感、轻量**：AsyncStorage/MMKV 都可（Expo 更常用 AsyncStorage；裸 RN 更常用 MMKV 性能更好）。

---

## 2) 哪些数据放 SQLite（结构化、本地可查询、可离线）

SQLite 的价值在于：**结构化、可索引、可查询、可增量更新**。只要你满足以下任一条件，就优先 SQLite。

### 适合 SQLite 的典型数据

1. **离线可用的数据**

   * 文章列表/详情、商品列表、消息列表、任务列表
   * 任何你希望“没网也能看”的内容

2. **数据量中等/较大，且需要查询**

   * 需要分页、筛选、排序、模糊搜索
   * 需要按时间范围查询、按状态筛选、按标签聚合

3. **有关系或结构化实体**

   * user / post / comment
   * project / task / tag / task_tag（多对多）
   * chat / message（典型：每次进会话要按会话 id + 时间分页）

4. **需要事务一致性**

   * 批量写入、同步时防止写一半中断
   * 离线编辑 → 联网后同步的“队列/日志（outbox）”

### 不建议 SQLite 的数据

* **超大二进制**（图片、视频、音频）：不要塞进 SQLite（BLOB 会导致 DB 变大、备份/迁移慢、碎片化）。
* **极小且不需要查询**：用 Key-Value 更简单。

---

## 3) 图片/文件放哪里（非常关键）

图片、附件、录音、视频等应放在 **文件系统**，数据库里只存**路径/URL/元信息**。

* 文件系统：`FileSystem.documentDirectory`（Expo）/ `app sandbox`（RN 原生）
* SQLite 里存：`localPath`, `remoteUrl`, `mime`, `size`, `hash`, `createdAt`

这样做的好处：

* 读取快、管理清晰
* DB 小且稳定
* 清理缓存、迁移更容易

---

## 4) SQLite 数据库“放到哪里”（你问的重点）

### 结论（你需要记住的）

SQLite 数据库文件最终都存放在**应用沙盒（App Sandbox）内部**，用户在系统文件管理器一般看不到，其他 App 也访问不到。

你不需要手动选择“放到哪个目录”，库会帮你放到正确位置。

### 在 Expo/RN 中大致位置（概念级）

* **iOS**：App 沙盒下的 `Documents/` 或 `Library/` 目录（由 SQLite 驱动/库决定）
* **Android**：`/data/data/<你的包名>/databases/`（典型 SQLite 默认路径）

> 这些路径属于系统受限区域：
>
> * iOS 非越狱不可见
> * Android 需要 root 或通过 Android Studio 的 Device File Explorer 查看（debug 可见）

你在代码里通常只需要提供 **数据库名称**（例如 `app.db`），不需要拼物理路径。

---

## 5) 一个“项目级分层方案”（你可以直接照着用）

### Key-Value（AsyncStorage/SecureStore）

* `auth.refreshToken`（SecureStore）
* `auth.accessToken`（可放内存 + SecureStore；accessToken 短期也可仅内存）
* `settings.theme`, `settings.lang`
* `cache.lastSyncAt`
* `flags.hasOnboarded`

### SQLite

* `users`、`posts`、`comments`
* `chats`、`messages`
* `outbox`（离线操作队列：待同步的新增/编辑/删除）
* `search_index`（若你要本地搜索）

### 文件系统

* `images/<hash>.jpg`
* `attachments/<id>.pdf`

---

## 6) 常见边界问题（快速规则）

* **“要不要离线可用？”**
  是 → SQLite / 文件系统
  否 → Key-Value / 内存即可

* **“需不需要按条件查询/分页？”**
  是 → SQLite
  否 → Key-Value 或直接网络

* **“是不是敏感数据？”**
  是 → SecureStore/Keychain/Keystore（不要 SQLite/AsyncStorage 明文）

* **“是不是二进制大文件？”**
  是 → 文件系统，SQLite 只存路径
