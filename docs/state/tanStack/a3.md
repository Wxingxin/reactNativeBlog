# 一、先建立一个「正确的缓存心智模型」

在 TanStack Query 里，每一条 Query 都有 **3 个关键状态维度**：

```
是否在缓存中？
是否是新鲜数据？
是否会被自动重新请求？
```

而你提到的这 4 个配置，**正是控制这 3 件事的开关**。

---

# 二、staleTime ——「多久算新鲜」

> **决定：会不会“自动重新请求”**

---

## 1️⃣ 什么是 stale（过期）？

* **fresh（新鲜）**：不会自动 refetch
* **stale（过期）**：可能触发自动 refetch

```ts
staleTime: 5 * 60 * 1000 // 5 分钟
```

👉 这 5 分钟内：

* 切换页面 ❌ 不请求
* 窗口聚焦 ❌ 不请求
* 多组件共享 ✅ 秒开

---

## 2️⃣ 默认行为（很多人不知道）

```ts
staleTime: 0
```

意味着：

> **数据一拿到，立刻就被标记为 stale**

所以你会看到：

* 切回页面就请求
* 聚焦窗口就请求
* 明明有缓存但还是打接口

---

## 3️⃣ 真实项目如何选择 staleTime？

| 场景      | 建议         |
| ------- | ---------- |
| 列表 / 详情 | 3 ~ 10 分钟  |
| 用户信息    | 10 ~ 30 分钟 |
| 实时数据    | 0          |
| 配置类数据   | Infinity   |

```ts
useQuery({
  staleTime: Infinity,
});
```

---

## 4️⃣ 一句话记忆

> **staleTime 决定“我信不信缓存”**

---

# 三、gcTime（cacheTime）——「不用多久就删」

> **决定：缓存什么时候被真正清掉**

---

## 1️⃣ 什么是 gcTime？

当 **没有任何组件在使用这个 Query** 时：

```ts
gcTime: 10 * 60 * 1000
```

表示：

* 10 分钟没人用 → 从内存移除
* 再访问 → 当作新 Query

---

## 2️⃣ 重要区别（面试/理解必考）

| 配置        | 作用      |
| --------- | ------- |
| staleTime | 会不会重新请求 |
| gcTime    | 会不会被删除  |

⚠️ **stale ≠ 被删除**

---

## 3️⃣ 举个关键例子

```ts
staleTime: 5 分钟
gcTime: 30 分钟
```

* 10 分钟后回来：

  * 数据是 stale
  * 但还在缓存
  * UI 先显示旧数据
  * 然后后台刷新

👉 **这就是“秒开 + 更新”体验**

---

## 4️⃣ 实际建议

| 类型  | gcTime     |
| --- | ---------- |
| 列表  | 10 ~ 30 分钟 |
| 详情  | 10 分钟      |
| 大数据 | 较短         |

---

## 5️⃣ 一句话记忆

> **gcTime 决定“我还记不记得你”**

---

# 四、refetchOnWindowFocus / refetchOnReconnect

> **决定：什么时候“自动同步服务器”**

---

## 1️⃣ 窗口聚焦（最常见）

```ts
refetchOnWindowFocus: true
```

* 切回浏览器
* Tab 从后台变前台
* 页面重新聚焦

⚠️ **只对 stale 数据生效**

---

## 2️⃣ 网络重连

```ts
refetchOnReconnect: true
```

* 网络断开 → 恢复
* 自动刷新数据

---

## 3️⃣ 真实项目推荐配置

```ts
queries: {
  refetchOnWindowFocus: false,
  refetchOnReconnect: true,
}
```

原因：

* 避免频繁请求
* 网络恢复时保证数据新

---

## 4️⃣ 一句话记忆

> **这些配置是“我什么时候主动问服务器”**

# 五、retry / retryDelay ——「失败了怎么办」

> **后端不稳定时非常关键**

---

## 1️⃣ retry 是什么？

```ts
retry: 2
```

* 请求失败
* 自动再试 2 次
* 默认是 `3`

---

## 2️⃣ retryDelay（指数退避）

```ts
retryDelay: (attempt) => Math.min(1000 * 2 ** attempt, 30000)
```

效果：

* 第 1 次失败 → 2s
* 第 2 次失败 → 4s
* 最多 30s

---

## 3️⃣ 哪些情况不该 retry？

```ts
retry: (failureCount, error) => {
  if (error.status === 401) return false;
  return failureCount < 2;
}
```

不该重试：

* 401（登录过期）
* 403（权限）
* 表单校验失败

---

## 4️⃣ 实战建议

| 场景   | retry |
| ---- | ----- |
| 列表   | 1~2   |
| 提交   | 0     |
| 实时接口 | 0     |
| 统计类  | 2~3   |

---

# 六、推荐的「默认策略模板」（直接可用）

```ts
const queryClient = new QueryClient({
  defaultOptions: {
    queries: {
      staleTime: 5 * 60 * 1000,
      gcTime: 10 * 60 * 1000,
      retry: 1,
      refetchOnWindowFocus: false,
      refetchOnReconnect: true,
    },
    mutations: {
      retry: 0,
    },
  },
});
```

---

# 七、你必须真正理解的一张逻辑图（文字版）

```
请求 → 成功 → 缓存
          ↓
       staleTime 到期？
          ↓
      是 → stale（可自动刷新）
      否 → fresh（只用缓存）

组件卸载
 ↓
gcTime 到期？
 ↓
是 → 删除缓存
否 → 保留
```
