# 一、Server State vs Client State

**为什么 TanStack Query 只管「服务端数据」**

## 1️⃣ 什么是 Client State（你已经很熟）

**客户端本地产生、只在前端存在的数据**

```ts
const [isOpen, setIsOpen] = useState(false);
const [theme, setTheme] = useState("dark");
```

特点：

* 不需要和后端同步
* 刷新页面就丢
* 完全由前端控制

👉 **UI 状态、表单状态、弹窗开关、选中项**
这些都 ❌ 不该交给 TanStack Query

---

## 2️⃣ 什么是 Server State（TanStack Query 的职责）

**来自后端、需要和服务器保持一致的数据**

```ts
GET /users
GET /users/1
POST /users
```

特点：

* 来源是服务器
* 有缓存 / 失效 / 刷新问题
* 多个组件可能用同一份数据
* 可能失败、重试、重新请求

👉 **列表、详情、搜索结果、统计数据**

---

## 3️⃣ 为什么不用 useEffect + useState 管？

你以前可能这样写：

```ts
useEffect(() => {
  fetchUsers().then(setUsers);
}, []);
```

问题：

* ❌ 没缓存（切页面再回来又请求）
* ❌ 没状态机（loading/error 手写）
* ❌ 多组件共享困难
* ❌ 刷新/重试/失效逻辑全靠你

👉 **TanStack Query = 专门解决 Server State 的“基础设施”**

---

# 二、Query Key

**缓存的唯一标识 & 参数化设计（非常重要）**

## 1️⃣ Query Key 是什么？

👉 **一个 Query 在缓存里的唯一身份证**

```ts
useQuery({
  queryKey: ["users"],
  queryFn: fetchUsers,
});
```

* 相同 key → 复用缓存
* 不同 key → 不同缓存

---

## 2️⃣ 参数化 Query Key（真实项目必用）

❌ 错误写法（会缓存错乱）：

```ts
useQuery({
  queryKey: ["user"],
  queryFn: () => fetchUserById(id),
});
```

✅ 正确写法：

```ts
useQuery({
  queryKey: ["user", id],
  queryFn: () => fetchUserById(id),
});
```

**规则：**

> 👉 **只要请求参数变了，key 一定要变**

---

## 3️⃣ 常见 Key 组织方式（推荐）

```ts
// queryKeys.ts
export const userKeys = {
  all: ["users"] as const,
  list: (params) => ["users", "list", params] as const,
  detail: (id) => ["users", "detail", id] as const,
};
```

好处：

* 统一
* 可维护
* invalidate 精准

---

# 三、useQuery

**拉取数据 + 缓存 + 状态机**

## 1️⃣ 基本使用

```ts
const {
  data,
  isLoading,
  isError,
  error,
} = useQuery({
  queryKey: ["users"],
  queryFn: fetchUsers,
});
```

你**自动得到**：

* loading
* error
* success
* 缓存
* 重新请求能力

---

## 2️⃣ 状态机本质（你要理解的核心）

```
idle
 ↓
loading
 ↓
success ❌ error
```

你不再需要：

```ts
const [loading, setLoading] = useState(false);
const [error, setError] = useState(null);
```

---

## 3️⃣ useQuery 的典型场景

* 列表页
* 详情页
* 搜索结果
* 只读数据

---

# 四、useMutation

**提交数据（新增 / 编辑 / 删除）**

> ❗原则：
> **“查数据用 useQuery，改数据用 useMutation”**

---

## 1️⃣ 基本使用

```ts
const mutation = useMutation({
  mutationFn: createUser,
});
```

调用：

```ts
mutation.mutate({
  name: "Tom",
});
```

---

## 2️⃣ mutation 的状态

```ts
mutation.isPending
mutation.isSuccess
mutation.isError
```

常见用法：

* 提交中禁用按钮
* 成功后提示
* 失败提示错误

---

## 3️⃣ 常见业务

* 新增
* 编辑
* 删除
* 点赞 / 收藏 / 提交表单

---

# 五、invalidateQueries

**提交后让列表“自动刷新”**

## 1️⃣ 为什么需要 invalidate？

你新增了一个用户：

```ts
POST /users
```

但列表是缓存的：

```ts
GET /users
```

👉 **缓存不知道你刚才改了数据**

---

## 2️⃣ 正确做法

```ts
const queryClient = useQueryClient();

const mutation = useMutation({
  mutationFn: createUser,
  onSuccess: () => {
    queryClient.invalidateQueries({
      queryKey: ["users"],
    });
  },
});
```

效果：

* 所有 `["users"]` 的 query 自动重新请求
* 列表立即更新

---

## 3️⃣ invalidate 的本质

> **不是清空数据，而是标记为“过期”**

下一次渲染 / 聚焦 / 访问 → 自动重新拉取

---

# 六、enabled

**条件请求（依赖数据再请求）**

## 1️⃣ 典型场景

* id 还没准备好
* 表单没提交前不请求
* 需要登录后再请求

---

## 2️⃣ 错误示例

```ts
useQuery({
  queryKey: ["user", id],
  queryFn: () => fetchUser(id),
});
```

当 `id = undefined` → ❌

---

## 3️⃣ 正确写法

```ts
useQuery({
  queryKey: ["user", id],
  queryFn: () => fetchUser(id),
  enabled: !!id,
});
```

规则：

> **enabled = false → 完全不请求**

---

## 4️⃣ 依赖请求示例

```ts
const { data: user } = useQuery({
  queryKey: ["me"],
  queryFn: fetchMe,
});

const userId = user?.id;

useQuery({
  queryKey: ["orders", userId],
  queryFn: () => fetchOrders(userId),
  enabled: !!userId,
});
```

---

# 七、select

**在 Query 层做数据映射（非常推荐）**

## 1️⃣ 为什么要用 select？

❌ 不推荐（组件层处理）：

```ts
const users = data?.map(u => ({
  label: u.name,
  value: u.id,
}));
```

问题：

* 每个组件都要写一遍
* 不利于复用
* UI 层逻辑变重

---

## 2️⃣ 使用 select（最佳实践）

```ts
useQuery({
  queryKey: ["users"],
  queryFn: fetchUsers,
  select: (data) =>
    data.map((u) => ({
      label: u.name,
      value: u.id,
    })),
});
```

好处：

* 数据结构统一
* 组件只负责渲染
* select 结果也会被缓存

---

## 3️⃣ select 常见用途

* 字段裁剪
* 格式化时间
* 后端结构适配前端
* 排序 / 过滤（轻量）

---

# 八、把所有点串成一个完整流程

👉 **真实项目 99% 都是这个模式：**

1. `useQuery` 拉列表
2. `useQuery` 拉详情（enabled）
3. `useMutation` 新增 / 编辑 / 删除
4. `invalidateQueries` 刷新列表
5. `select` 做数据映射
6. Query Key 统一管理
