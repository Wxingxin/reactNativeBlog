## 4.1 全局错误与提示体系

### A. 统一错误模型：先把“错误类型”说清楚

在工程里建议把错误分成 3 类（足够覆盖 99% 情况）：

1. **业务错误（Business Error）**：后端返回 200/4xx，但业务 code 表示失败

* 例如：`{ code: 40001, message: "库存不足" }`

2. **鉴权错误（Auth Error）**：401/403

* 401：token 过期/无效，需要刷新或跳登录
* 403：无权限（通常提示“无权限”即可）

3. **网络/系统错误（Network/System Error）**：断网、超时、5xx

* 例如：`ECONNABORTED`、`Network Error`、500/502/503

建议做一个统一错误类（或至少统一 shape），这样 Query 的 onError 才能写得干净。

#### 示例：统一错误类型（TypeScript）

```ts
export type AppErrorKind = "BUSINESS" | "AUTH" | "NETWORK" | "UNKNOWN";

export class AppError extends Error {
  kind: AppErrorKind;
  status?: number;
  code?: string | number;
  detail?: unknown;

  constructor(message: string, kind: AppErrorKind, opts?: Partial<AppError>) {
    super(message);
    this.kind = kind;
    Object.assign(this, opts);
  }
}
```

### B. QueryClient 默认 onError（配合 toast）

TanStack Query 的“全局 onError”适合做两件事：

* **统一 toast 提示（但要避免 401 这种会被鉴权层处理的错误重复提示）**
* **统一上报监控（Sentry/自建日志）**

#### QueryClient 推荐配置

```ts
import { QueryClient } from "@tanstack/react-query";

const toast = {
  error: (msg: string) => console.error("[toast.error]", msg),
  success: (msg: string) => console.log("[toast.success]", msg),
};

export const queryClient = new QueryClient({
  defaultOptions: {
    queries: {
      retry: (failureCount, error: any) => {
        // 鉴权错误、业务错误通常不重试
        if (error?.kind === "AUTH" || error?.kind === "BUSINESS") return false;
        // 网络类可以小幅重试
        return failureCount < 1;
      },
      refetchOnWindowFocus: false,
    },
    mutations: {
      retry: false,
    },
  },
});
```

> TanStack Query 并没有一个“全局默认 onError”直接放在 QueryClient 构造里统一覆盖所有 query 的选项（你可以在自定义 hook 或 queryFn 层做统一包装）。工程上更常见的做法是：
>
> * “错误归一化”放到 **HTTP 层**（axios/fetch wrapper）
> * “toast 展示策略”放到 **QueryCache/MutationCache** 或你自定义 hooks 中

更稳的一种全局方案：用 QueryCache/MutationCache（适合“全局 toast”）

```ts
import { QueryClient, QueryCache, MutationCache } from "@tanstack/react-query";

export const queryClient = new QueryClient({
  queryCache: new QueryCache({
    onError: (error: any) => {
      if (error?.kind === "AUTH") return; // 401 交给鉴权层处理
      toast.error(getUserFriendlyMessage(error));
    },
  }),
  mutationCache: new MutationCache({
    onError: (error: any) => {
      if (error?.kind === "AUTH") return;
      toast.error(getUserFriendlyMessage(error));
    },
  }),
});
```

配套一个“错误文案策略”函数：

```ts
function getUserFriendlyMessage(err: any): string {
  if (err?.kind === "BUSINESS") return err.message || "操作失败";
  if (err?.kind === "NETWORK") return "网络异常，请稍后重试";
  return "系统异常，请稍后重试";
}
```

### C. 统一处理 401：token 过期跳登录

**关键原则：401 不要在每个页面/每个 useQuery 里处理。**
应该在 **HTTP 层拦截器**里处理（axios interceptor 或 fetch wrapper），保证“只处理一次”。

处理路径通常是：

* 401 → 尝试 refresh token

  * refresh 成功：重放原请求
  * refresh 失败：清 token → 跳登录 → 可 toast “登录已过期”

> 这样 Query 层收到的错误要么已经被重试成功，要么是“最终失败（refresh 失败）”的 AUTH 错误。

---

### D. 区分业务错误 vs 网络错误（展示文案策略不同）

推荐规则（足够实用）：

* **业务错误**：直接展示后端 message（比如“库存不足”“用户名已存在”）
* **网络错误**：用统一文案（“网络异常/系统繁忙”），避免把技术细节暴露给用户
* **401**：不弹“请求失败”，弹“登录过期”并跳登录（避免重复 toast）

## 4.2 鉴权与 Token 刷新

下面给你两套：axios 拦截器版（最常见） + fetch wrapper 版（也很干净）。你选其一即可，别混用。

---

### 方案 1：axios 拦截器（推荐）

#### A. 自动带 token（request 拦截器）

```ts
import axios, { AxiosError, AxiosRequestConfig } from "axios";
import { AppError } from "./AppError";

export const http = axios.create({
  baseURL: "/api",
  timeout: 15000,
});

function getAccessToken() {
  return localStorage.getItem("access_token");
}

http.interceptors.request.use((config) => {
  const token = getAccessToken();
  if (token) config.headers.Authorization = `Bearer ${token}`;
  return config;
});
```

---

#### B. refresh token 流程：并发时“只刷新一次”（关键）

核心思想：

* 用一个全局 `refreshPromise`（或 `isRefreshing` + queue）
* 多个请求同时 401：

  * 第一个触发 refresh
  * 后续请求等待 refreshPromise
  * refresh 成功后统一重放

示例实现（可直接用）：

```ts
let refreshPromise: Promise<string> | null = null;

function getRefreshToken() {
  return localStorage.getItem("refresh_token");
}

function setAccessToken(token: string) {
  localStorage.setItem("access_token", token);
}

function clearTokens() {
  localStorage.removeItem("access_token");
  localStorage.removeItem("refresh_token");
}

async function refreshAccessToken(): Promise<string> {
  const refreshToken = getRefreshToken();
  if (!refreshToken) throw new AppError("No refresh token", "AUTH");

  // 注意：refresh 请求本身不要走同一个拦截器循环触发 401
  const res = await axios.post("/api/auth/refresh", { refreshToken });
  const newToken = res.data?.accessToken;
  if (!newToken) throw new AppError("Refresh failed", "AUTH");

  setAccessToken(newToken);
  return newToken;
}

// 防止无限重试：给请求打标记
type RetryConfig = AxiosRequestConfig & { _retry?: boolean };

http.interceptors.response.use(
  (res) => res.data, // 可按你后端结构调整
  async (err: AxiosError) => {
    // 网络错误（无响应）
    if (!err.response) {
      return Promise.reject(new AppError("Network error", "NETWORK", { detail: err }));
    }

    const status = err.response.status;
    const config = err.config as RetryConfig | undefined;

    // 业务错误归一化（示例：后端 message/code）
    const data: any = err.response.data;

    // 401：鉴权
    if (status === 401 && config && !config._retry) {
      config._retry = true;

      try {
        if (!refreshPromise) {
          refreshPromise = refreshAccessToken().finally(() => {
            refreshPromise = null;
          });
        }
        const newToken = await refreshPromise;
        config.headers = config.headers ?? {};
        config.headers.Authorization = `Bearer ${newToken}`;

        // 重放原请求
        return http(config);
      } catch (e) {
        // refresh 失败：清理并跳登录
        clearTokens();
        // 这里触发你的路由跳转：window.location 或 router.navigate
        window.location.href = "/login";
        return Promise.reject(new AppError("登录已过期，请重新登录", "AUTH", { status }));
      }
    }

    // 403：权限错误
    if (status === 403) {
      return Promise.reject(new AppError("无权限访问", "AUTH", { status, detail: data }));
    }

    // 业务错误（按你后端约定判断）
    // 例如：{ code, message }
    if (data?.message) {
      return Promise.reject(new AppError(data.message, "BUSINESS", { status, code: data.code, detail: data }));
    }

    // 其他：系统错误
    return Promise.reject(new AppError("系统异常", "UNKNOWN", { status, detail: data }));
  }
);
```

**这段代码解决了：**

* 自动带 token
* 401 自动刷新并重放
* 并发 401 只刷新一次（refreshPromise）
* refresh 失败统一跳登录
* 错误统一归一化为 AppError（Query 层很好处理）

## 与 TanStack Query 的配合方式（落地建议）

1. **所有 queryFn/mutationFn 都调用 `http`（已归一化错误）**
2. QueryCache/MutationCache 统一 toast：

   * AUTH 不 toast（交给拦截器跳登录/提示）
   * BUSINESS toast 后端 message
   * NETWORK toast “网络异常”
3. mutations 默认不 retry；queries 小幅 retry（网络类）

---

## 最常见的“重复提示”问题怎么避免？

重复发生在：

* axios 拦截器已经 toast 了一次
* Query 全局 onError 又 toast 一次

解决策略：

* toast 只放一个地方：**推荐放 QueryCache/MutationCache**
* axios 层只负责：

  * 归一化错误类型
  * 处理 401 refresh/跳登录
  * 不 toast（或只对 refresh 失败 toast）
