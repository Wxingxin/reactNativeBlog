下面把 **TanStack Query 的两种分页范式**讲透，并给你“可直接复制到项目”的写法与关键注意点。你学会这两套，实际项目 90% 的列表都能覆盖。

---

# 一、传统分页：page + pageSize（核心是 keepPreviousData）

目标体验：

* 翻页时**不闪白**
* 旧页数据先显示，新页数据在后台加载出来再替换
* 支持“跳页、切 pageSize、搜索筛选”

## 1）关键点与心智模型

传统分页的 Query Key 必须包含分页参数：

* ✅ `["users", { page, pageSize, keyword }]`
* ❌ `["users"]`（会导致缓存串页）

“keepPreviousData 思路”本质是：

> page 变化时，先保留上一页 data，让 UI 不空；同时发起新请求，回来后替换。

在 TanStack Query v5 中，你通常用：

* `placeholderData: keepPreviousData`

（很多教程还写 `keepPreviousData: true`，那是旧版本/旧写法思路。）

---

## 2）代码示例（传统分页完整可用）

### API（page/pageSize）

```ts
// 返回：{ items: User[]; total: number }
export async function fetchUsersPage(params, signal?: AbortSignal) {
  const res = await fetch(`/api/users?page=${params.page}&pageSize=${params.pageSize}&q=${params.q ?? ""}`, { signal });
  if (!res.ok) throw new Error("fetch failed");
  return res.json();
}
```

### 组件

```tsx
import { useQuery, keepPreviousData } from "@tanstack/react-query";

export function UsersPage() {
  const [page, setPage] = useState(1);
  const [pageSize, setPageSize] = useState(10);
  const [q, setQ] = useState("");

  const params = { page, pageSize, q };

  const usersQuery = useQuery({
    queryKey: ["users", params],
    queryFn: ({ signal }) => fetchUsersPage(params, signal),
    placeholderData: keepPreviousData, // 关键：保留上一页数据
    staleTime: 30 * 1000,
  });

  const data = usersQuery.data;
  const total = data?.total ?? 0;
  const totalPages = Math.ceil(total / pageSize);

  return (
    <div>
      <input value={q} onChange={(e) => { setPage(1); setQ(e.target.value); }} placeholder="搜索用户" />

      <select value={pageSize} onChange={(e) => { setPage(1); setPageSize(Number(e.target.value)); }}>
        <option value={10}>10</option>
        <option value={20}>20</option>
        <option value={50}>50</option>
      </select>

      {usersQuery.isFetching && <p>正在加载新页（旧数据仍显示）...</p>}

      <ul>
        {data?.items?.map((u) => (
          <li key={u.id}>{u.name}</li>
        ))}
      </ul>

      <button disabled={page <= 1} onClick={() => setPage((p) => p - 1)}>
        上一页
      </button>
      <span>{page} / {Math.max(totalPages, 1)}</span>
      <button disabled={page >= totalPages} onClick={() => setPage((p) => p + 1)}>
        下一页
      </button>
    </div>
  );
}
```

## 3）传统分页的“工程级”注意点

* 翻页 loading 状态用 `isFetching` 更合适（因为 data 可能仍在显示）
* 搜索/筛选变化时，**通常要把 page 重置为 1**
* 可以预取下一页提升体验：

```ts
const queryClient = useQueryClient();
useEffect(() => {
  if (page < totalPages) {
    queryClient.prefetchQuery({
      queryKey: ["users", { ...params, page: page + 1 }],
      queryFn: ({ signal }) => fetchUsersPage({ ...params, page: page + 1 }, signal),
    });
  }
}, [page, pageSize, q, totalPages]);
```

# 二、无限滚动：useInfiniteQuery（cursor 或 page 递增）

目标体验：

* 下拉/触底加载更多
* 已加载的数据持续累积
* 支持 cursor（更推荐）或 page 递增

---

## A. Cursor 分页（更推荐）

### 1）后端返回格式（典型）

```ts
type PageResult<T> = {
  items: T[];
  nextCursor: string | null; // 没有更多时为 null
};
```

### 2）useInfiniteQuery 写法（cursor）

```tsx
import { useInfiniteQuery } from "@tanstack/react-query";

export function FeedPage() {
  const q = ""; // 也可以是搜索关键字

  const feedQuery = useInfiniteQuery({
    queryKey: ["feed", { q }],
    queryFn: async ({ pageParam, signal }) => {
      const cursor = pageParam ?? null;
      const res = await fetch(`/api/feed?cursor=${cursor ?? ""}&q=${encodeURIComponent(q)}`, { signal });
      if (!res.ok) throw new Error("fetch failed");
      return res.json(); // { items, nextCursor }
    },
    initialPageParam: null,
    getNextPageParam: (lastPage) => lastPage.nextCursor, // 关键
  });

  const items = feedQuery.data?.pages.flatMap((p) => p.items) ?? [];

  return (
    <div>
      <ul>
        {items.map((x) => <li key={x.id}>{x.title}</li>)}
      </ul>

      <button
        disabled={!feedQuery.hasNextPage || feedQuery.isFetchingNextPage}
        onClick={() => feedQuery.fetchNextPage()}
      >
        {feedQuery.isFetchingNextPage ? "加载中..." : feedQuery.hasNextPage ? "加载更多" : "没有更多了"}
      </button>
    </div>
  );
}
```

### 3）cursor 的优势

* 不怕数据插入/删除导致页码错乱
* 更适合内容流、聊天记录、时间线

---

## B. Page 递增（也可用，但更容易受数据变化影响）

如果后端只支持 `page=1,2,3...`，也可以用 infinite：

```tsx
useInfiniteQuery({
  queryKey: ["feed"],
  queryFn: ({ pageParam = 1, signal }) => fetch(`/api/feed?page=${pageParam}`, { signal }).then(r => r.json()),
  initialPageParam: 1,
  getNextPageParam: (lastPage, allPages) => {
    // lastPage.hasMore 由后端返回，或根据 total 推算
    return lastPage.hasMore ? allPages.length + 1 : undefined;
  },
});
```

# 三、传统分页 vs 无限滚动：怎么选

| 维度      | 传统分页（page/pageSize） | 无限滚动（infinite）           |
| ------- | ------------------- | ------------------------ |
| 典型产品形态  | 管理后台、报表、检索列表        | 内容流、社区、商品瀑布流             |
| URL 可分享 | 更容易（page 在 URL）     | 需要额外处理                   |
| 数据稳定性   | 相对稳定                | cursor 更稳；page 递增可能受插入影响 |
| 性能风险    | 低（只渲染一页）            | 高（累计数据，需要虚拟列表）           |
| 用户体验    | 跳页强                 | 浏览连续强                    |

---

# 四、你必须掌握的细节（面试/实战高频）

1. **分页参数必须进 Query Key**（否则缓存串）
2. 传统分页：用 `placeholderData: keepPreviousData` 避免闪白
3. 无限滚动：`getNextPageParam` 决定能不能继续拉
4. 无限滚动数据量大时，后续要配 **虚拟列表**（TanStack Virtual / react-window）
