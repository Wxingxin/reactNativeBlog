下面按你列的 2.2、2.3 逐项讲清楚，并给你一套“可以直接落地到项目里”的写法与习惯。为了避免概念漂浮，我统一用一个业务例子串起来：

* 先拿当前登录用户 `GET /me`
* 再用 `user.id` 拉订单列表 `GET /users/:id/orders`
* 同时并发拉：订单统计、优惠券、推荐商品
* 支持取消请求（切页/输入变化时终止上一请求）
* 数据整形用 `select`，组件只吃自己要的字段

# 2.2 依赖与并发控制

## A. 依赖请求：先拿 user，再用 userId 拉 list（enabled）

### 1）关键原则

1. **上游 Query 的结果**是下游 Query 的入参
2. 下游 Query 必须 `enabled: !!userId`，否则会出现 `undefined` 请求或错误 key
3. 下游 Query Key 必须包含 `userId`（否则缓存会串）

### 2）推荐写法（两段 Query，清晰稳定）

```tsx
import { useQuery } from "@tanstack/react-query";
import { userKeys } from "./queryKeys/user.keys";
import { fetchMe, fetchOrdersByUserId } from "./api";

export function OrdersPage() {
  // ① 先拿当前用户
  const meQuery = useQuery({
    queryKey: ["me"],
    queryFn: fetchMe,
    staleTime: 10 * 60 * 1000,
  });

  const userId = meQuery.data?.id;

  // ② 再用 userId 拉订单列表（依赖请求）
  const ordersQuery = useQuery({
    queryKey: ["orders", userId],
    queryFn: () => fetchOrdersByUserId(userId), // 这里 userId 已经存在
    enabled: !!userId, // 关键：没有 userId 就不请求
  });

  if (meQuery.isLoading) return <p>加载用户中...</p>;
  if (meQuery.isError) return <p>用户加载失败</p>;

  if (ordersQuery.isLoading) return <p>加载订单中...</p>;
  if (ordersQuery.isError) return <p>订单加载失败</p>;

  return (
    <ul>
      {ordersQuery.data.map((o) => (
        <li key={o.id}>{o.title}</li>
      ))}
    </ul>
  );
}
```

### 3）常见坑与正确姿势

* 坑：`queryKey: ["orders"]` 不带 userId → A 用户缓存会被 B 用户复用
* 坑：`enabled` 忘记加 → `fetchOrdersByUserId(undefined)`
* 姿势：把依赖关系写“显式”：`const userId = meQuery.data?.id;`

## B. 并发请求：useQueries（多个 query 并行）

当你需要在同一个页面同时拉多个互不依赖的数据时，用 `useQueries` 可以：

* 并行发请求（更快）
* 代码更规整（比多个 useQuery 更集中）

### 1）典型场景

* 页面初始化：订单列表 + 统计 + 优惠券 + 推荐
* Dashboard：多个卡片同时请求

### 2）写法（并行）

```tsx
import { useQueries } from "@tanstack/react-query";
import {
  fetchOrdersByUserId,
  fetchOrderStats,
  fetchCoupons,
  fetchRecommendations,
} from "./api";

export function Dashboard({ userId }: { userId: string }) {
  const results = useQueries({
    queries: [
      {
        queryKey: ["orders", userId],
        queryFn: () => fetchOrdersByUserId(userId),
        enabled: !!userId,
      },
      {
        queryKey: ["orderStats", userId],
        queryFn: () => fetchOrderStats(userId),
        enabled: !!userId,
      },
      {
        queryKey: ["coupons", userId],
        queryFn: () => fetchCoupons(userId),
        enabled: !!userId,
      },
      {
        queryKey: ["reco", userId],
        queryFn: () => fetchRecommendations(userId),
        enabled: !!userId,
      },
    ],
  });

  const [ordersQ, statsQ, couponsQ, recoQ] = results;

  if (results.some((r) => r.isLoading)) return <p>加载中...</p>;
  if (results.some((r) => r.isError)) return <p>部分数据加载失败</p>;

  return (
    <div>
      <div>订单数：{statsQ.data.count}</div>
      <div>优惠券：{couponsQ.data.length}</div>
      <div>推荐：{recoQ.data.length}</div>
      <ul>{ordersQ.data.map((o) => <li key={o.id}>{o.title}</li>)}</ul>
    </div>
  );
}
```

### 3）工程建议

* 如果某个请求需要另一个请求的数据（有依赖），不要硬塞进 useQueries；拆开用 `enabled` 做依赖更清晰。
* `useQueries` 很适合“卡片式并行数据”。

## C. 取消请求：与 fetch 的 AbortController 配合

取消请求的价值在于：

* 用户切页面 / 切 Tab / 搜索输入变化很快 → **终止旧请求，避免浪费**
* 避免竞态：旧请求比新请求后返回导致 UI 闪烁（Query 本身在 key 变化上能缓解，但取消更彻底）

### 1）TanStack Query 的关键点

在 `queryFn` 里会收到一个 `signal`，你要把它传给 fetch：

```ts
queryFn: async ({ signal }) => { ... }
```

### 2）fetch + signal 正确写法（推荐）

```ts
export async function fetchUsers(params, signal?: AbortSignal) {
  const url = new URL("/api/users", window.location.origin);
  Object.entries(params).forEach(([k, v]) => url.searchParams.set(k, String(v)));

  const res = await fetch(url.toString(), { signal });
  if (!res.ok) throw new Error("Failed to fetch users");
  return res.json();
}
```

在 useQuery 里：

```tsx
useQuery({
  queryKey: ["users", params],
  queryFn: ({ signal }) => fetchUsers(params, signal),
});
```

### 3）axios 怎么办？

axios 从 v1 开始也支持 `signal`，同样传进去即可（如果你项目里用 axios，优先统一在 http 层透传 signal）。

# 2.3 数据转换与组件解耦

## A. 在 Query 的 select 做数据整形

### 1）为什么要在 select 做？

* 组件层少写 map/format
* 多处复用同一数据形状
* 数据转换集中管理，后端字段变更更好维护
* `select` 的结果也会被缓存（组件拿到的就是“处理好”的数据）

### 2）示例：把后端订单数据整成 UI 需要的形状

假设后端返回：

```ts
type Order = {
  id: string;
  title: string;
  total_cents: number;
  created_at: string;
  status: "pending" | "paid";
};
```

组件只想要：

```ts
type OrderCardVM = {
  id: string;
  title: string;
  total: string;      // "￥12.34"
  createdAt: string;  // "2026-01-22"
  badge: "待支付" | "已支付";
};
```

用 `select`：

```tsx
const ordersQuery = useQuery({
  queryKey: ["orders", userId],
  queryFn: () => fetchOrdersByUserId(userId),
  enabled: !!userId,
  select: (orders) =>
    orders.map((o) => ({
      id: o.id,
      title: o.title,
      total: `￥${(o.total_cents / 100).toFixed(2)}`,
      createdAt: o.created_at.slice(0, 10),
      badge: o.status === "paid" ? "已支付" : "待支付",
    })),
});
```

组件里就非常干净：

```tsx
return ordersQuery.data.map((vm) => <OrderCard key={vm.id} {...vm} />);
```

---

## B. 组件只消费“需要的形状”，不要到处 map/format

### 1）推荐的分层习惯

* **API 层**：只负责请求与返回原始数据
* **Query 层（select）**：把原始数据转换成业务/视图模型
* **UI 组件**：只渲染，不做复杂转换

这样你后期做：

* 国际化
* 金额/时间格式统一
* 多端复用（React / RN）
  都会更顺。

### 2）进阶建议：把 select 抽成纯函数

```ts
export const toOrderCardVM = (o: Order): OrderCardVM => ({
  id: o.id,
  title: o.title,
  total: `￥${(o.total_cents / 100).toFixed(2)}`,
  createdAt: o.created_at.slice(0, 10),
  badge: o.status === "paid" ? "已支付" : "待支付",
});
```

```tsx
select: (orders) => orders.map(toOrderCardVM)
```
