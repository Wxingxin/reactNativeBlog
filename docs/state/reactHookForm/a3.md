下面给你一份 **JS + JSX** 视角的「`useForm` + `Zod` 在项目中常见配置大全 + 对应知识点大全」。重点是：你在真实项目里怎么配、怎么写、怎么避免坑，而不是只罗列 API。

---

## 0）它们在项目中的分工（先建立心智模型）

* **React Hook Form（useForm）**：管“表单交互与状态”（收集值、提交、错误落点、性能）
* **Zod**：管“数据契约”（结构、类型、复杂校验、转换）
* **resolver（桥梁）**：让 RHF 把收集到的数据交给 Zod 校验，再把错误映射回 `formState.errors`

---

## 1）安装与最小闭环（项目标准接入方式）

```bash
npm i zod @hookform/resolvers
```

最小可运行示例（JS/JSX）：

```jsx
import React from "react";
import { useForm } from "react-hook-form";
import { z } from "zod";
import { zodResolver } from "@hookform/resolvers/zod";

const schema = z.object({
  email: z.string().email("邮箱格式不正确"),
  password: z.string().min(6, "至少 6 位"),
});

export default function Login() {
  const {
    register,
    handleSubmit,
    formState: { errors, isSubmitting },
  } = useForm({
    defaultValues: { email: "", password: "" },
    resolver: zodResolver(schema),
    mode: "onSubmit",
    reValidateMode: "onChange",
  });

  const onSubmit = async (data) => {
    await new Promise((r) => setTimeout(r, 400));
    console.log("submit:", data);
  };

  return (
    <form onSubmit={handleSubmit(onSubmit)} style={{ display: "grid", gap: 12 }}>
      <div>
        <input placeholder="email" {...register("email")} />
        {errors.email?.message && <p style={{ color: "crimson" }}>{errors.email.message}</p>}
      </div>

      <div>
        <input type="password" placeholder="password" {...register("password")} />
        {errors.password?.message && <p style={{ color: "crimson" }}>{errors.password.message}</p>}
      </div>

      <button disabled={isSubmitting}>{isSubmitting ? "Submitting..." : "Submit"}</button>
    </form>
  );
}
```

## 2）`useForm + zod` 常见配置大全（项目最常用）

以下是实际项目里最常见、最值得统一的配置项。

### A. `resolver: zodResolver(schema)`（必配）

**解决什么问题**：把所有校验集中在 schema；错误自动映射到 `errors`。

```jsx
useForm({
  resolver: zodResolver(schema),
});
```

**知识点**

* 有了 resolver 后，通常不再写 `register("x", rules)`（可以写，但建议统一用 schema 管校验，减少重复规则）

---

### B. `defaultValues` + Zod：默认值与回填（高频坑点）

```jsx
useForm({
  defaultValues: { name: "", tags: [] },
  resolver: zodResolver(schema),
});
```

**知识点（必记）**

* `defaultValues` 只初始化读取一次
* 编辑页异步数据回填：**用 `reset(fetched)`**，不是改 defaultValues

```jsx
const form = useForm({ defaultValues, resolver: zodResolver(schema) });

React.useEffect(() => {
  fetchDetail().then((data) => form.reset(data));
}, [form]);
```

---

### C. `mode / reValidateMode`：校验时机（和 schema 配合的 UX）

**推荐组合（后台表单）**

```jsx
useForm({
  resolver: zodResolver(schema),
  mode: "onSubmit",
  reValidateMode: "onChange",
});
```

**推荐组合（C 端即时反馈）**

```jsx
useForm({
  resolver: zodResolver(schema),
  mode: "onBlur",
  reValidateMode: "onChange",
  delayError: 150,
});
```

**知识点**

* schema 校验可能较重，`onChange` 会更频繁触发；对超大表单要谨慎。

---

### D. `shouldUnregister`：条件字段是否提交（和 Zod 条件校验强相关）

```jsx
useForm({
  shouldUnregister: true,
  resolver: zodResolver(schema),
});
```

**场景**

* “开关打开才出现 A 字段”，关闭时 A 字段不提交——推荐 `true`

**知识点**

* `shouldUnregister: true` 时，隐藏字段会从数据中移除；你的 schema 要允许它“缺席”（optional），或用条件校验控制。

---

### E. `criteriaMode`：一次给用户展示多个 schema 错误

```jsx
useForm({
  resolver: zodResolver(schema),
  criteriaMode: "all",
});
```

**场景**

* 密码强度/复杂规则，想一次性展示多个点

---

### F. `context`：给 schema 条件校验提供上下文（中高级但很实用）

例如：同一个表单在“创建/编辑”规则不同。

```jsx
useForm({
  resolver: zodResolver(schema),
  context: { isEdit: true },
});
```

**知识点**

* 你可以在 schema 的 refine/superRefine 里使用这个上下文（取决于 resolver 实现与写法；常见做法是把 isEdit 作为参数构造 schema，更清晰）。

更推荐（工程更稳）：**用函数生成 schema**

```jsx
const buildSchema = ({ isEdit }) =>
  z.object({
    email: z.string().email(),
    password: isEdit ? z.string().optional() : z.string().min(6),
  });
```

## 3）Zod Schema 在表单里的“常见写法大全”（项目核心）

### 3.1 基础字段：string/number/boolean/array/object

```jsx
const schema = z.object({
  title: z.string().min(1, "标题必填"),
  age: z.number().int().min(0),
  isPublic: z.boolean(),
  tags: z.array(z.string()).min(1, "至少选择一个标签"),
  profile: z.object({
    nickname: z.string().min(1, "昵称必填"),
  }),
});
```

---

### 3.2 数字字段：HTML input 返回 string 的处理（最常见坑）

**坑**：`<input type="number" />` 很多情况下你拿到的是 string（或空值导致 NaN）。

项目常用解法有两种（选一种统一团队风格）：

#### 方案 A：RHF 层转换（推荐，最直观）

```jsx
<input
  type="number"
  {...register("age", { valueAsNumber: true })}
/>
```

schema：

```jsx
age: z.number({ invalid_type_error: "年龄必须是数字" }).min(0),
```

#### 方案 B：Zod coerces（字符串转数字）

```jsx
age: z.coerce.number().min(0, "年龄不能小于 0"),
```

**知识点**

* `z.coerce.number()` 会把 `"18"` 转成 `18`，也可能把 `""` 转成 `0` 或 NaN 相关行为，需测试并配合 refine/optional 兜底

---

### 3.3 条件校验：开关控制字段必填（高频业务）

例如：`isCompany=true` 时 `companyName` 必填。

```jsx
const schema = z
  .object({
    isCompany: z.boolean(),
    companyName: z.string().optional(),
  })
  .superRefine((data, ctx) => {
    if (data.isCompany && !data.companyName?.trim()) {
      ctx.addIssue({
        code: z.ZodIssueCode.custom,
        path: ["companyName"],
        message: "公司名称必填",
      });
    }
  });
```

**知识点**

* 用 `superRefine` 可以精确把错误打到某个字段 `path`
* 这比在组件里 watch + setError 更稳定、更可维护

---

### 3.4 交叉字段校验：确认密码

```jsx
const schema = z
  .object({
    password: z.string().min(6, "至少 6 位"),
    confirmPassword: z.string().min(1, "请确认密码"),
  })
  .refine((data) => data.password === data.confirmPassword, {
    path: ["confirmPassword"],
    message: "两次密码不一致",
  });
```

---

### 3.5 表单值清洗：trim / transform（强烈建议）

把“输入脏数据”在提交前统一清洗，而不是到处 `trim()`。

```jsx
const schema = z.object({
  username: z.string().trim().min(3, "至少 3 位"),
});
```

**知识点**

* `.trim()` 是 Zod string 的常用链式方法
* 更复杂清洗可用 `.transform()`（但 transform 会改变输出类型/值，建议团队统一约定）

---

## 4）`useForm` 与 schema 的“常用落地模板”（三类项目）

### 4.1 后台编辑页（异步回填 + 保留用户已改字段）

```jsx
const form = useForm({
  defaultValues,
  resolver: zodResolver(schema),
  mode: "onSubmit",
  reValidateMode: "onChange",
  resetOptions: { keepDirtyValues: true },
});
```

配合回填：

```jsx
React.useEffect(() => {
  fetchDetail().then((data) => form.reset(data));
}, [form]);
```

---

### 4.2 条件字段很多（隐藏就不提交）

```jsx
useForm({
  defaultValues,
  resolver: zodResolver(schema),
  shouldUnregister: true,
});
```

schema 里对应字段通常 `optional()`，再用 `superRefine` 做条件必填。

---

### 4.3 即时错误但不想太“吵”

```jsx
useForm({
  defaultValues,
  resolver: zodResolver(schema),
  mode: "onBlur",
  reValidateMode: "onChange",
  delayError: 150,
});
```

## 5）服务端错误与 Zod 的协作（项目必做）

Zod 负责客户端结构校验，但服务端仍可能返回字段错误（例如“邮箱已注册”）。

典型做法：服务端错误 → `setError`

```jsx
const { setError } = useForm({ resolver: zodResolver(schema) });

try {
  await api.save(data);
} catch (e) {
  // 假设后端返回 { fieldErrors: { email: "已注册" } }
  setError("email", { type: "server", message: "邮箱已注册" });
}
```

**知识点**

* schema 校验通过 ≠ 服务端必定成功
* 客户端结构校验 + 服务端业务校验，是两层不同的防线

---

## 6）高频踩坑清单（useForm + Zod）

1. **默认值与回填**：异步回填一定用 `reset()`
2. **number 类型**：要么 `valueAsNumber`，要么 `z.coerce.number()`，别混用导致类型漂移
3. **条件字段**：配 `shouldUnregister` 时 schema 要允许缺席（optional）并用 superRefine 控制必填
4. **重复规则**：不要同时在 `register` rules 和 schema 写同一套校验（维护成本翻倍）
5. **transform 过度**：transform 改变输出，团队最好统一规则（例如只做 trim、number coercion）

---

## 7）你在项目里最推荐形成的“规范”

* 所有校验集中在 **Zod schema**
* `useForm` 统一配置：`mode/reValidateMode/shouldUnregister` 等
* 值类型在“输入层”或“schema 层”统一清洗（不要提交前到处处理）
* 服务端字段错误统一用 `setError` 映射
