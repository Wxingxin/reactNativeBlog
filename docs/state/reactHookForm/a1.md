下面给你一份面向 **JavaScript + JSX（不使用 TypeScript）** 的 `useForm` 常见配置大全与项目知识点。内容按“你在项目里最常用、最容易踩坑、最值得统一成团队规范”的顺序组织，并配套可直接复制使用的代码片段。

---

## 1）JS/JSX 项目里的基础模板（推荐先用这套）

适用于大多数后台表单：先提交再校验，失败后再边改边校验，体验和性能平衡。

```jsx
import React from "react";
import { useForm } from "react-hook-form";

export default function BasicTemplateForm() {
  const {
    register,
    handleSubmit,
    formState: { errors, isSubmitting, isDirty, isValid },
    reset,
  } = useForm({
    defaultValues: {
      email: "",
      password: "",
    },
    mode: "onSubmit",
    reValidateMode: "onChange",
    shouldFocusError: true,
    criteriaMode: "firstError",
    shouldUnregister: true,
    delayError: 200,
  });

  const onSubmit = async (data) => {
    // 模拟提交
    await new Promise((r) => setTimeout(r, 600));
    console.log("submit:", data);

    // 提交成功后重置（可按需）
    reset();
  };

  return (
    <form onSubmit={handleSubmit(onSubmit)} style={{ display: "grid", gap: 12 }}>
      <div>
        <input
          placeholder="email"
          {...register("email", {
            required: "邮箱必填",
            pattern: { value: /^\S+@\S+$/i, message: "邮箱格式不正确" },
          })}
        />
        {errors.email?.message && <p style={{ color: "crimson" }}>{errors.email.message}</p>}
      </div>

      <div>
        <input
          type="password"
          placeholder="password"
          {...register("password", {
            required: "密码必填",
            minLength: { value: 6, message: "至少 6 位" },
          })}
        />
        {errors.password?.message && (
          <p style={{ color: "crimson" }}>{errors.password.message}</p>
        )}
      </div>

      <button disabled={isSubmitting}>
        {isSubmitting ? "Submitting..." : "Submit"}
      </button>

      <small>
        isDirty: {String(isDirty)} | isValid: {String(isValid)}
      </small>
    </form>
  );
}
```

## 2）`useForm` 常见配置项大全（JS 项目常用版）

### A. `defaultValues`：默认值（最常用）

**解决**：初始化表单值、重置基准。

```jsx
useForm({
  defaultValues: {
    name: "",
    age: 18,
  },
});
```

**关键知识点（必记）**

* `defaultValues` 只在初始化读取一次
* 编辑页异步回填不要改 defaultValues，用 `reset(fetched)`（下面会讲）

---

### B. `mode`：第一次何时触发校验（非常常改）

**解决**：用户何时看到错误提示。

可选：

* `"onSubmit"`：提交时才校验（默认）
* `"onBlur"`：失焦校验
* `"onChange"`：输入即校验
* `"all"`：多时机触发（更“严格/吵”）

```jsx
useForm({ mode: "onBlur" });
```

**项目建议**

* 登录/注册：`onBlur` 或 `onChange`（更即时）
* 长表单/后台：`onSubmit`（更安静）

---

### C. `reValidateMode`：首次失败后，后续怎么重新校验

**解决**：避免用户提交失败后，还得再次提交才看到更新的错误。

```jsx
useForm({
  mode: "onSubmit",
  reValidateMode: "onChange",
});
```

**推荐组合**

* `mode: "onSubmit" + reValidateMode: "onChange"`（最常见）

---

### D. `shouldFocusError`：提交失败自动聚焦第一个错误字段

**解决**：长表单定位错误更快。

```jsx
useForm({ shouldFocusError: true });
```

**注意**

* 自定义滚动容器、移动端可能出现滚动跳动；必要时关闭后自己滚动定位。

---

### E. `criteriaMode`：一个字段返回“一个错误”还是“多个错误”

**解决**：密码复杂规则时一次提示多个问题。

```jsx
useForm({ criteriaMode: "all" }); // 或 "firstError"(默认)
```

**场景**

* 密码：长度/数字/大写/特殊字符等想一次性提示

---

### F. `shouldUnregister`：字段卸载时是否从表单中移除（条件字段必看）

**解决**：隐藏字段是否参与提交、是否保留值。

```jsx
useForm({ shouldUnregister: true });
```

**选择建议**

* 多步骤表单：通常 `false`（切步不丢值）
* 条件字段（开关控制显示）：通常 `true`（隐藏就不提交）

---

### G. `delayError`：延迟错误显示，减少“输入就红”

**解决**：`onChange` 校验时提升体验。

```jsx
useForm({ delayError: 300 });
```

---

### H. `disabled`：整张表单禁用（只读/权限）

**解决**：详情页/无权限用户复用同一表单组件。

```jsx
useForm({ disabled: true });
```

---

### I. `values`：外部值驱动表单（少用，但一旦用要谨慎）

**解决**：表单值完全受外部状态控制（例如切换模板强制覆盖）。

```jsx
useForm({ values: externalValues });
```

**风险**

* 外部 values 一变化，可能覆盖用户正在输入的内容（常见 bug）

---

### J. `resetOptions`：控制 reset 时保留哪些状态（编辑页高级常用）

**解决**：编辑页数据刷新时不覆盖用户已修改字段。

```jsx
useForm({
  resetOptions: {
    keepDirtyValues: true,
    keepErrors: false,
    keepTouched: false,
  },
});
```

---

### K. `context`：传给 resolver 的上下文（配合 Zod/Yup）

JS 项目也可以用（当你用 resolver 时）。

```jsx
useForm({ context: { isEdit: true } });
```

## 3）编辑页异步回填：`reset()` 的正确姿势（项目最常见）

**问题**：请求回来的数据要显示在表单里。

✅ 正解：拿到数据后 `reset(data)`
（不要依赖更新 `defaultValues`）

```jsx
import React from "react";
import { useForm } from "react-hook-form";

export default function EditProfile() {
  const { register, reset, handleSubmit } = useForm({
    defaultValues: { nickname: "", bio: "" },
  });

  React.useEffect(() => {
    (async () => {
      const data = await fetch("/api/profile").then((r) => r.json());
      reset(data); // ✅ 回填
    })();
  }, [reset]);

  return (
    <form onSubmit={handleSubmit((d) => console.log(d))}>
      <input {...register("nickname")} />
      <textarea {...register("bio")} />
      <button>Save</button>
    </form>
  );
}
```

## 4）条件字段：配合 `shouldUnregister` 的经典写法

比如：勾选后才出现 companyName，隐藏时不提交。

```jsx
import React from "react";
import { useForm } from "react-hook-form";

export default function ConditionalField() {
  const { register, watch, handleSubmit } = useForm({
    defaultValues: { isCompany: false, companyName: "" },
    shouldUnregister: true, // 关键
  });

  const isCompany = watch("isCompany");

  return (
    <form onSubmit={handleSubmit(console.log)} style={{ display: "grid", gap: 10 }}>
      <label>
        <input type="checkbox" {...register("isCompany")} />
        公司用户
      </label>

      {isCompany && (
        <input
          placeholder="公司名称"
          {...register("companyName", { required: "公司名称必填" })}
        />
      )}

      <button>Submit</button>
    </form>
  );
}
```

## 5）项目里最常用的 `formState`（你会一直用）

```jsx
const {
  formState: {
    errors,        // 字段错误
    isSubmitting,  // 提交中（适合 loading）
    isDirty,       // 是否修改过（是否提示“未保存”）
    isValid,       // 是否整体通过（要配合 mode）
    submitCount,   // 提交次数（做 UX 逻辑很实用）
  },
} = useForm();
```

**实践建议**

* 按需解构，避免不必要订阅导致渲染（在复杂页面里更明显）
* `isValid` 在 `mode: "onSubmit"` 下不会实时更新（这是很多人误会点）
