下面给你一份 **JS + JSX** 的「`useForm` 结合 UI（组件库/自定义组件）在项目中常见配置大全 + 知识点大全」。这里的“UI”包括：原生控件、第三方组件库（AntD/MUI/Radix/shadcn 等）、以及你自己封装的表单字段组件。核心目标是：**让表单字段“可复用、可维护、一致体验、错误展示统一”。**

---

## 1）useForm + UI 的整体架构（项目里最常见的分层）

建议你把表单拆成三层（长期维护最稳）：

1. **Page 层**：请求数据、提交、路由、权限
2. **Form 层**：表单结构与分组（Section）
3. **Field 层（UI 字段组件）**：输入控件 + label + error + help + layout

在这一套里：

* `useForm` 通常在 **Form 层**初始化
* `control/register/errors` 传给 Field 或通过 `FormProvider` 下发

## 2）useForm 在“UI集成”时最常见的配置项大全（高频）

下面这些配置项，几乎都是为了 UI 交互与体验服务的。

### A. `defaultValues`：让 UI 控件有稳定初始值（必配）

```jsx
const form = useForm({
  defaultValues: {
    title: "",
    category: "",      // Select
    enabled: false,    // Switch
    tags: [],          // MultiSelect
    date: null,        // DatePicker（按组件约定）
  },
});
```

**知识点**

* UI 控件非常怕 `undefined`（会出现受控/非受控警告或显示异常）
* 所以对 UI 集成来说，`defaultValues` 的意义比“数据默认值”还大：它是 **类型/形态稳定器**

---

### B. `mode / reValidateMode`：决定 UI 错误提示出现的节奏（强相关）

**推荐（后台表单）**

```jsx
useForm({
  mode: "onSubmit",
  reValidateMode: "onChange",
  delayError: 150,
});
```

**推荐（C 端即时）**

```jsx
useForm({
  mode: "onBlur",
  reValidateMode: "onChange",
  delayError: 120,
});
```

**知识点**

* UI 组件往往更“重”，频繁校验会导致体验变差
* `delayError` 能显著减少“输入就红”的干扰

---

### C. `shouldFocusError`：提交失败自动聚焦 + UI 自动定位（高频体验项）

```jsx
useForm({ shouldFocusError: true });
```

**知识点**

* 对原生 input 聚焦通常没问题
* 对某些 UI 组件（Select/DatePicker）聚焦可能无效或导致滚动跳动
* 复杂场景可关闭它，然后自定义“滚动到第一个错误字段”

---

### D. `shouldUnregister`：和 UI 的“条件字段/动态渲染”强绑定

```jsx
useForm({ shouldUnregister: true });
```

**典型 UI 场景**

* Switch 打开才显示某个输入框/下拉框
* Tabs 切换导致字段卸载

**知识点**

* `true`：隐藏字段不提交（通常更符合产品预期）
* `false`：隐藏字段仍会提交（对 UI 来说更容易引发“用户看不到但却提交了”的问题）

---

### E. `criteriaMode`：UI 是否一次展示多个错误（密码规则常用）

```jsx
useForm({ criteriaMode: "all" });
```

**知识点**

* UI 组件常要求“错误列表”，例如密码强度提示多条规则

---

### F. `resetOptions`：编辑页回填时，UI 是否保留用户已改值（常见需求）

```jsx
useForm({
  resetOptions: { keepDirtyValues: true },
});
```

**典型场景**

* 编辑页回填：接口返回更新了部分字段，但不希望覆盖用户正在编辑的字段

---

### G. `disabled`：UI 统一只读/禁用模式（复用同套组件）

```jsx
useForm({ disabled: isReadOnly });
```

**知识点**

* 适合“详情页/无权限”复用编辑页 UI

## 3）RHF 与 UI 的三种集成方式（项目最常见）

### 方式 1：原生控件：`register`（优先）

```jsx
<input {...register("title", { required: "标题必填" })} />
```

适合：input/textarea/原生 select/checkbox/radio
优点：简单、性能最好。

---

### 方式 2：第三方 UI 控件：`Controller`（高频）

```jsx
<Controller
  name="category"
  control={control}
  rules={{ required: "分类必选" }}
  render={({ field, fieldState }) => (
    <MySelect
      value={field.value}
      onChange={field.onChange}
      onBlur={field.onBlur}
      error={!!fieldState.error}
      helperText={fieldState.error?.message}
    />
  )}
/>
```

适合：Select、DatePicker、Autocomplete、富文本、Upload 等。

---

### 方式 3：封装统一 Field 组件：`useController`（工程化必备）

你会在项目里做出这样的组件：

* `<RHFInput />`
* `<RHFSelect />`
* `<RHFSwitch />`
* `<RHFDatePicker />`

这样页面只负责“摆字段”，错误、label、布局都统一。

## 4）UI 常见控件“桥接配置大全”（高频模式）

下面是你在项目里最常遇到的几类 UI 控件对接方式。

### A. Select（onChange(value)）

```jsx
<Controller
  name="category"
  control={control}
  rules={{ required: "分类必选" }}
  render={({ field, fieldState }) => (
    <>
      <MySelect value={field.value} onChange={(v) => field.onChange(v)} />
      {fieldState.error?.message && <p>{fieldState.error.message}</p>}
    </>
  )}
/>
```

### B. Switch/Checkbox（checked）

```jsx
<Controller
  name="enabled"
  control={control}
  render={({ field }) => (
    <MySwitch checked={!!field.value} onCheckedChange={field.onChange} />
  )}
/>
```

### C. DatePicker（Date/null）

```jsx
<Controller
  name="date"
  control={control}
  rules={{ required: "请选择日期" }}
  render={({ field }) => (
    <MyDatePicker value={field.value} onChange={field.onChange} />
  )}
/>
```

### D. 多选（数组）

```jsx
<Controller
  name="tags"
  control={control}
  rules={{ validate: (arr) => (arr?.length ? true : "至少选一个标签") }}
  render={({ field }) => (
    <MyMultiSelect value={field.value || []} onChange={field.onChange} />
  )}
/>
```

### E. 输入需要格式化（金额/手机号）

保持 RHF 存“业务值”，UI 做格式化：

```jsx
<Controller
  name="price"
  control={control}
  rules={{ required: "价格必填" }}
  render={({ field }) => (
    <MoneyInput
      value={field.value == null ? "" : String(field.value)}
      onChangeText={(text) => field.onChange(parseMoney(text))}
      onBlur={field.onBlur}
    />
  )}
/>
```

## 5）表单 UI 组件封装的“推荐规范”（强烈建议你这么做）

### 5.1 `FormProvider`：避免 props 传递爆炸

```jsx
import { FormProvider, useForm, useFormContext } from "react-hook-form";

function RHFTextField({ name, label }) {
  const { register, formState: { errors } } = useFormContext();
  return (
    <div>
      <label>{label}</label>
      <input {...register(name)} />
      {errors[name]?.message && <p>{errors[name].message}</p>}
    </div>
  );
}

export default function Page() {
  const methods = useForm({ defaultValues: { title: "" } });
  return (
    <FormProvider {...methods}>
      <form onSubmit={methods.handleSubmit(console.log)}>
        <RHFTextField name="title" label="标题" />
      </form>
    </FormProvider>
  );
}
```

**知识点**

* UI 组件封装越多，`FormProvider` 越能减少传参噪音
* 但不要在“很小的表单”里过度使用，保持适度

---

### 5.2 字段组件统一输出：`label / required / error / helperText / disabled`

建议你封装字段组件时，统一支持这几个 props，使页面结构一致。

示例（useController 版本）：

```jsx
import React from "react";
import { useController } from "react-hook-form";

export function RHFSelect({ name, control, label, rules, SelectComp, disabled }) {
  const { field, fieldState } = useController({ name, control, rules });

  return (
    <div style={{ display: "grid", gap: 6 }}>
      {label && <label>{label}</label>}
      <SelectComp
        value={field.value}
        onChange={field.onChange}
        onBlur={field.onBlur}
        disabled={disabled}
      />
      {fieldState.error?.message && <p style={{ color: "crimson" }}>{fieldState.error.message}</p>}
    </div>
  );
}
```

## 6）UI 集成里最常见的坑（必看清单）

1. **undefined 导致受控/非受控警告**

   * 解决：`defaultValues` 保证字段值形态稳定（""、false、[]、null）
2. **UI 组件 onChange 参数不是 event**

   * 解决：手动 `field.onChange(value)` 映射
3. **Switch/Checkbox 不是 value 而是 checked**

   * 解决：`checked={!!field.value}`
4. **DatePicker 值类型不一致**（string/Date）

   * 解决：统一约定“表单内部存 Date”，提交时再格式化
5. **条件字段隐藏仍提交**

   * 解决：`shouldUnregister: true` 或隐藏时手动清理
6. **错误展示不统一**

   * 解决：字段组件统一渲染 error/helperText（useController 最方便）

## 7）项目里最常用的一套“UI + useForm 默认配置模板”

你可以把它当作团队默认：

```jsx
const form = useForm({
  defaultValues,              // UI 值稳定
  mode: "onSubmit",           // 首次校验
  reValidateMode: "onChange", // 失败后边改边校验
  shouldUnregister: true,     // 条件字段隐藏不提交
  shouldFocusError: true,     // 提交失败定位
  delayError: 150,            // 降低输入噪音
});
```
